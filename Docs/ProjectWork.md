# Проектная работа: Warflame

## Общая информация

`Warflame` — короткая демо-игра в жанре third-person sci-fi action / shooter с квестовой целью.

Проект разработан на Unreal Engine 5.7 в рамках учебного проекта `UE_Learning`. В качестве основного референса выбран `Warframe`: проект использует sci-fi окружение, персонажа от третьего лица, противников, стрельбу, перемещение по уровню и выполнение боевой квестовой задачи.

Игра собирается как packaged build для Windows. Итоговый исполняемый файл сдаётся как `UE_Learning.exe`.

Ориентировочная длительность первого прохождения — около 15 минут.

## Цель проектной работы

Цель проектной работы — собрать короткую демо-игру с полным игровым циклом:

1. запуск из главного меню;
2. переход на проектную карту;
3. получение задания у NPC-квестодателя;
4. выполнение боевой и исследовательской цели;
5. сбор квестовых предметов;
6. победа над командиром;
7. уничтожение требуемого количества врагов;
8. возврат к квестодателю;
9. завершение задания;
10. показ финального экрана.

Проект не делался как отдельный изолированный уровень. Он продолжает архитектуру, созданную в домашних работах: базовые классы персонажей, Gameplay Ability System, систему взаимодействия, NPC, State Tree, UI, оружие, projectile, аудио, VFX и локализацию.

## Жанр и референс

Жанр проекта:

- third-person sci-fi action;
- shooter;
- квестовая демо-игра с боевым заданием.

Референс:

- `Warframe`.

Из референса взята общая идея sci-fi боевого сценария: игрок управляет персонажем от третьего лица, перемещается по уровню, взаимодействует с заданием, сражается с группой противников и выполняет цель до финального завершения.

## Игровой цикл на 10+ минут

Проект рассчитан на короткое первое прохождение примерно на 15 минут.

Игровой цикл:

1. Игрок запускает билд.
2. Открывается главное меню.
3. Игрок выбирает запуск проектной карты.
4. На карте игрок находит Хранителя.
5. Хранитель выдаёт задание.
6. Игрок получает цель найти контейнер с биоматериалом.
7. Игрок должен победить командира захватчиков.
8. После смерти командира появляется древний инструмент.
9. Игрок собирает древний инструмент.
10. Игрок уничтожает 100 захватчиков.
11. После выполнения условий игрок возвращается к Хранителю.
12. Хранитель принимает задание.
13. Появляется экран завершения.

Игровой цикл считается завершённым после сдачи задания Хранителю и появления финального экрана.

## Главное меню

В проект добавлено главное меню.

Используются:

- уровень `L_Project_MainMenu`;
- Widget Blueprint `WBP_ProjectMainMenu`;
- C++ класс `TPMainMenuWidget`.

Главное меню содержит:

- запуск проектной карты;
- выбор уровня;
- выход из игры.

В меню также есть панель выбора уровня. Через неё можно перейти на проектную карту, карту с большинством домашних заданий и карту домашней работы по Landscape.

Тексты главного меню задаются через `FText` в C++ и поддерживают локализацию. Визуальное оформление остаётся в Blueprint.

## Игровой персонаж

Основной игровой персонаж построен на существующей архитектуре проекта:

- `TPBaseCharacter`;
- `TPPlayerCharacter`;
- `TPAttributeSet`;
- `TPCharacterAnimInstance`;
- `TPWeaponEquipmentComponent`.

Игрок умеет:

- перемещаться;
- смотреть мышью;
- прыгать;
- приседать;
- идти шагом;
- бежать;
- использовать sprint;
- делать dash;
- взаимодействовать с объектами;
- целиться;
- стрелять;
- получать урон;
- умирать;
- видеть экран смерти.

Управление реализовано через Enhanced Input и `TPInputConfig`, где действия привязаны к Gameplay Tags. Это позволяет расширять управление без добавления отдельных полей под каждое действие в классе персонажа.

## NPC

В проекте есть несколько типов NPC:

- Хранитель;
- обычные захватчики;
- командир захватчиков.

NPC используют общую архитектуру:

- `TPNPCCharacter`;
- `TPNPCDefinition`;
- `TPNPCAIController`;
- State Tree;
- AI Perception;
- `FGenericTeamId`.

Хранитель является квестодателем. Он не используется как боевой NPC и не должен случайно погибать во время прохождения.

Захватчики являются враждебными NPC. Они патрулируют уровень, обнаруживают игрока, преследуют его и ведут огонь.

Командир является уникальной целью задания. После его смерти через менеджер цели появляется древний инструмент.

## Квестовая система

Проектная карта использует квестовую систему на основе:

- `TPQuestGiverComponent`;
- `TPQuestTextDefinition`;
- `TPLevelObjectiveManager`;
- `TPQuestItemActor`.

Хранитель выдаёт задание. После принятия задания игрок должен выполнить несколько условий:

- подобрать контейнер с биоматериалом;
- победить командира захватчиков;
- подобрать древний инструмент;
- уничтожить 100 захватчиков;
- вернуться к Хранителю.

`TPLevelObjectiveManager` управляет состоянием задания, прогрессом предметов, счётчиком убийств и показом экрана завершения.

## Квестовые предметы

Для проектной карты используются два квестовых предмета:

- `BP_QuestItem_BiomaterialContainer`;
- `BP_QuestItem_AncientTool`.

Оба предмета работают через общий C++ класс `TPQuestItemActor`.

Контейнер с биоматериалом размещён на карте и становится доступен по сценарию задания.

Древний инструмент появляется после смерти командира захватчиков. Дроп инструмента централизован в `TPLevelObjectiveManager`, чтобы логика появления квестового предмета находилась в одном месте и не дублировалась на NPC.

## Противники и AI

Противники используют State Tree и AI Controller.

В поведении захватчиков реализованы:

- патрулирование по NavMesh;
- ожидание между точками патруля;
- обнаружение игрока через AI Perception;
- преследование цели;
- стрельба на дистанции;
- распространение тревоги на ближайших союзников;
- поиск последней известной позиции игрока;
- проверка безопасной линии огня;
- смена позиции при риске friendly fire.

Параметры AI вынесены в `TPNPCDefinition`. Через Data Asset настраиваются:

- радиус патруля;
- скорость патруля;
- скорость преследования;
- радиус зрения;
- дистанция стрельбы;
- интервал выстрела;
- радиус тревоги союзников;
- параметры поиска последней известной позиции;
- параметры безопасной линии огня.

Так новые разновидности NPC можно создавать через настройки, не дублируя C++ логику.

## Оружие и бой

Оружие подключено через `TPWeaponEquipmentComponent`.

Основные классы боевой системы:

- `TPWeaponDefinition`;
- `TPWeaponEquipmentComponent`;
- `TPWeaponActor`;
- `TPBlasterProjectile`.

`TPWeaponActor` отвечает за выстрел:

- проверяет интервал между выстрелами;
- создаёт projectile;
- передаёт урон;
- передаёт Gameplay Effect;
- проигрывает звук выстрела;
- вызывает Blueprint-событие для VFX.

`TPBlasterProjectile` отвечает за попадание:

- применяет урон через Gameplay Ability System;
- проигрывает звук попадания;
- вызывает VFX попадания;
- определяет попадание в голову для враждебных NPC.

## UI

В проекте используются несколько UI-экранов:

- главное меню;
- меню паузы;
- HUD цели;
- подсказка взаимодействия;
- экран смерти;
- экран завершения задания.

Основные C++ классы UI:

- `TPMainMenuWidget`;
- `TPPauseMenuWidget`;
- `TPMessageScreenWidget`;
- `InteractionPromptWidget`;
- `TPHealthBarWidget`.

Меню паузы открывается во время игры клавишей `Esc`. При открытии игра ставится на паузу, включается курсор мыши и управление переключается в UI-only режим.

Экран смерти появляется при смерти игрока.

Экран завершения появляется после сдачи задания Хранителю.

## Аудио

Звуковая логика персонажей вынесена в компонент:

- `TPCharacterAudioComponent`.

Компонент отвечает за:

- звуки шагов;
- звук сердцебиения при низком здоровье;
- остановку сердцебиения при смерти игрока.

Автоматический детект шагов по умолчанию выключен, чтобы NPC не выполняли лишние трассировки каждый кадр. Для главного персонажа автоматический детект шагов включается в Blueprint-настройках компонента.

Также в проекте используются:

- звук выстрела;
- звук попадания в тело;
- звук попадания в голову;
- звук падения тела NPC;
- ambient-звук окружения.

## VFX

VFX подключены через Blueprint-события, которые вызываются из C++.

Используются Niagara System assets:

- `NS_HW7_MuzzleFlash`;
- `NS_HW7_ImpactSpark`;
- `NS_HW7_NPCImpactBurst`.

C++ отвечает за игровые события: выстрел, попадание, смерть и урон. Blueprint отвечает за конкретное визуальное оформление эффектов.

## Модели и ассеты окружения

Окружающие модели и визуальные ассеты не состоят только из примитивов.

Для проекта использованы ассеты из:

- Mixamo;
- Fab.

Mixamo использовался для персонажей и анимаций.

Fab использовался для визуальных ассетов и окружения.

## Локализация

В проекте используется локализация через Unreal Localization Dashboard.

Локализованы:

- главное меню;
- меню паузы;
- экран смерти;
- экран завершения;
- подсказки взаимодействия;
- окно задания;
- прогресс сбора предметов;
- прогресс уничтожения захватчиков;
- названия и подсказки квестовых предметов.

Runtime-переключение языка выполняется через `AUE_LearningPlayerController::SetGameLanguage`.

Для packaged build в настройки упаковки добавлены культуры:

- `en`;
- `ru-RU`.

## Завершение игры

Игра считается пройденной, когда игрок:

1. принимает задание у Хранителя;
2. собирает контейнер с биоматериалом;
3. побеждает командира;
4. получает древний инструмент;
5. уничтожает 100 захватчиков;
6. возвращается к Хранителю;
7. сдаёт задание;
8. видит экран завершения.

Таким образом проект имеет полный игровой цикл от главного меню до финального экрана.


## Итог

`Warflame` представляет собой короткую sci-fi action / shooter демо-игру от третьего лица. Проект объединяет системы, разработанные в домашних работах, в единый игровой сценарий: главное меню, игровой уровень, квестодатель, боевые NPC, командир, квестовые предметы, счётчик убийств, UI, аудио, VFX, локализацию и завершающий экран.

Архитектура проекта остаётся расширяемой: базовые классы и компоненты переиспользуются, параметры вынесены в `UPROPERTY` и Data Asset, Blueprint отвечает за настройку ассетов, UI и визуальные эффекты, а C++ содержит общую игровую логику.
