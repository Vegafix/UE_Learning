- направление движения;
- состояние падения;
- состояние приседа;

- вниз выполняется trace для определения расстояния до земли;
- учитываются текущая вертикальная скорость и гравитация;
- вычисляется `TimeToImpact`;
- anticipation pose включается, когда `TimeToImpact` меньше заданного `LandingLeadTime`.

Так момент включения landing-анимации становится стабильнее при разных скоростях падения и разных высотах.

## Домашняя работа 5 — создание NPC  
### Промежуточный этап

Начата реализация масштабируемой системы NPC, рассчитанной не только на выполнение домашней работы, но и на дальнейшее развитие проекта.

### Базовая архитектура NPC

Добавлены C++ классы и структуры данных:

- `TPNPCCharacter` — базовый класс NPC;
- `TPNPCAIController` — AI-контроллер NPC;
- `TPNPCDefinition` — Data Asset с настраиваемыми параметрами NPC;
- `TPNPCTypes` — общие типы и перечисления для системы NPC.

Созданы два типа NPC:

- `BP_NPC_Bandit` — враждебный NPC;
- `BP_NPC_Researcher` — нейтральный NPC.

Параметры конкретных NPC вынесены в отдельные Data Asset:

- `DA_NPC_Bandit`;
- `DA_NPC_Researcher`.

Это позволяет создавать новые разновидности NPC без дублирования основной C++-логики.

### Поведение враждебного NPC

Для разбойника создан State Tree:

- `ST_NPC_Bandit`.

На текущем этапе реализованы состояния:

- `Move To Random Point` — выбор случайной точки на NavMesh и движение к ней;
- `Wait Before Next Point` — пауза между этапами патрулирования;
- `Chase Target` — преследование обнаруженной цели;
- `Fire At Target` — остановка и выполнение тестового выстрела по цели.

Для State Tree добавлены переиспользуемые C++-задачи и вычисляемые данные:

- поиск случайной точки патрулирования;
- переключение скорости передвижения NPC;
- получение текущей цели;
- вычисление дистанции до цели;
- проверка дистанции стрельбы;
- проверка прямой видимости цели;
- тестовый одиночный выстрел из текущего оружия.

### Обнаружение игрока

В `TPNPCAIController` подключена система `AI Perception`.

NPC:

- обнаруживает игрока;
- назначает его текущей целью;
- переходит от патрулирования к преследованию;
- сохраняет цель при кратковременной потере видимости;
- забывает цель только после заданной задержки;
- возвращается к патрулированию после потери цели.

Задержка забывания цели вынесена в настройки NPC через `TargetForgetDelay`.

### Анимации NPC

Для NPC создан отдельный Animation Blueprint:

- `ABP_NPC_Humanoid`.

Добавлены:

- Blend Space передвижения;
- вычисление скорости и направления движения;
- анимации патрулирования и преследования;
- поддержка удержания оружия двумя руками.

Для левой руки используется `Two Bone IK`:

- винтовка прикрепляется к сокету правой кисти;
- левая кисть процедурно подтягивается к `LeftHandIKTarget`, расположенному внутри оружия.

### Общая система экипировки

Логика создания и хранения оружия вынесена из класса игрока в общий компонент:

- `TPWeaponEquipmentComponent`.

Компонент используется базовым персонажем и подходит как для игрока, так и для NPC.

Добавлен Data Asset оружия:

- `TPWeaponDefinition`;
- `DA_Weapon_Rifle`.

Через него задаются:

- класс Actor оружия;
- имя сокета крепления;
- индивидуальная поправка положения оружия;
- точка выхода выстрела.

Одна и та же винтовка `BP_RifleWeapon` теперь может использоваться главным персонажем и враждебным NPC.

### Подготовка системы стрельбы

В `TPWeaponActor` добавлен компонент:

- `MuzzlePoint` — точка выхода пули у среза ствола.

Для проверки направления оружия реализована отладочная визуализация:

- сфера в позиции `MuzzlePoint`;
- линия вдоль направления ствола.

Добавлен временный тестовый метод одиночного выстрела:

- `DebugFireOnce`.

Метод выполняет line trace от `MuzzlePoint` до текущей цели NPC и выводит результат в лог.

Для выстрелов создан отдельный trace-канал:

- `WeaponTrace`.

Это отделяет обработку попаданий оружия от каналов взаимодействия, обзора AI и стандартного `Visibility`.

На промежуточном этапе реализовано:

- патрулирование разбойника;
- обнаружение игрока;
- преследование игрока;
- возврат к патрулированию после потери цели;
- удержание винтовки двумя руками;
- стрельба одиночными тестовыми trace-выстрелами с заданным интервалом;
- блокирование выстрелов препятствиями через канал `WeaponTrace`.

Урон, анимации выстрела, визуальные эффекты, звук и полноценная логика нейтрального NPC будут добавлены на следующих этапах.

### Развитие системы боя и здоровья

Система тестовой стрельбы была заменена на полноценную projectile-based стрельбу.

Добавена на полноценную projectile-based стрельбу.

Добавлен C++ класс снаряда:

- `TPBlasterProjectile`.

Снаряд создаётся из `MuzzlePoint` текущего оружия и летит в заданную точку с помощью `ProjectileMovementComponent`.

Для оружия расширен `TPWeaponDefinition`. Через Data Asset теперь задаются:

Для винтовки используется Blueprint-снаряд:

- `BP_BlasterProjectile`.

Визуальная часть выстрела вынесена в Blueprint:

- дополнительный след за снарядом;
- вспышка у дула оружия;

### Нанесение урона через Gameplay Ability System

В `TPAttributeSet` добавлены атрибуты:

- `Health`;
- `MaxHealth`;
- `MoveSpeed`;
- `Damage`.

Атрибут `Damage` используется как meta-attribute. При применении Gameplay Effect значение урона обрабатывается в `PostGameplayEffectExecute`, после чего здоровье персонажа уменьшается и ограничивается диапазоном от `0` до `MaxHealth`.

Для настройки начального здоровья создан Gameplay Effect:

- `GE_CharacterDefaults`.

Для нанесения урона оружием создан Gameplay Effect:

- `GE_WeaponDamage`.

Величина урона передаётся через Set By Caller tag:

- `Data.Damage`.

Так логика урона не привязана напрямую к конкретному оружию и может переиспользоваться для разных типов снарядов и атак.

### Смерть персонажей

В базовый класс персонажа добавлена общая логика смерти:

- проверка состояния смерти;
- остановка движения;
- отмена активных способностей;
- вызов Blueprint-события `OnDeath`;
- multicast-событие `OnCharacterDeath`.

Для NPC смерть дополнительно останавливает AI-логику:

- очищается текущая цель;
- останавливается State Tree;
- отключается AI Perception;
- отключается дальнейшая обработка восприятия цели.

Это предотвращает ситуацию, при которой мёртвый NPC продолжает обнаруживать игрока или стрелять после смерти.

Для NPC также добавлен ragdoll после смерти. Для разбойника был создан отдельный исправленный Physics Asset, так как исходная физика приводила к некорректному поведению ragdoll.

### Стрельба игрока

Для игрока добавлена стрельба из текущего оружия.

В систему ввода добавлен новый Gameplay Tag:

- `Input.Fire`.

Через `TPInputConfig` к нему привязан Input Action выстрела.

Игрок выполняет trace от камеры и передаёт найденную точку попадания в текущее оружие. Оружие создаёт снаряд, который летит в эту точку. Благодаря этому одна и та же система оружия используется и игроком, и NPC.

### Интерфейс здоровья

Добавлен переиспользуемый C++ виджет:

- `TPHealthBarWidget`.

На его основе созданы Blueprint-виджеты:

- `WBP_NPCHealthBar` — полоска здоровья над NPC;
- `WBP_PlayerHealthHUD` — полоска здоровья игрока на экране.

NPC получают `WidgetComponent` с полоской здоровья над головой. Виджет подписывается на изменение атрибутов `Health` и `MaxHealth` и обновляется при получении урона.

Игроку добавлен экранный виджет здоровья, который создаётся при старте игры и также обновляется через данные `TPAttributeSet`.

При смерти персонажа соответствующий health bar скрывается.

На данном этапе реализовано:

- projectile-based стрельба игрока и NPC;
- общий Data Asset оружия для настройки урона, снаряда и скорострельности;

### Экран смерти игрока и завершение цели уровня

После добавления здоровья и смерти персонажей был реализован минимальный игровой цикл уровня.

Для игрока добавлен экран смерти:

- `WBP_PlayerDeathScreen`.

Экран появляется после смерти `TPPlayerCharacter`, скрывает игровой HUD, переводит управление в UI-режим и показывает кнопку перезапуска уровня.

В `TPPlayerCharacter` добавлена настройка:

- `PlayerDeathScreenWidgetClass`.

Это позволяет назначать конкретный Blueprint-виджет экрана смерти через `BP_TPPlayerCharacter`, не привязывая C++ код к конкретному UMG-ассету.

Для перезапуска уровня используется кнопка в `WBP_PlayerDeathScreen`. Перед открытием уровня управление возвращается в игровой режим, чтобы после рестарта снова работали движение, камера и ввод игрока.

Также добавлен отдельный менеджер цели уровня:

- `TPLevelObjectiveManager`;
- `BP_LevelObjective_KillBandits`.

Менеджер размещается на уровне и содержит список NPC, смерть которых считается условием выполнения цели. Он подписывается на событие смерти персонажа `OnCharacterDeath` и отслеживает количество живых целей.

После уничтожения всех указанных NPC появляется экран завершения цели:

- `WBP_ObjectiveCompleteScreen`.

Экран завершения цели использует ту же общую схему перезапуска уровня, что и экран смерти игрока.

Так логика победы не привязана напрямую к конкретному NPC Blueprint. На уровне можно задать один или несколько целевых NPC через массив `Target NPCs`, а сам механизм завершения цели остаётся переиспользуемым.

### Текущее состояние игрового цикла

На текущем этапе реализованы две базовые ветки завершения уровня:

- игрок погибает от атаки NPC — появляется экран смерти и доступен перезапуск уровня;
- игрок уничтожает всех целевых NPC — появляется экран выполнения цели и доступен перезапуск уровня.

Система построена через отдельные C++ классы и Blueprint-настройки, поэтому в дальнейшем её можно расширить до полноценной системы заданий, волн врагов или условий прохождения уровня без переписывания логики персонажей и оружия.
