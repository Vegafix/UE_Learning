Учебный проект на Unreal Engine 5.7 для выполнения домашних работ по курсу Unreal Engine Game Developer.

---

## Домашняя работа 1

Реализован автоматический тест `UE_Learning.PlayerControllerDefaults`, который проверяет валидность CDO пользовательского `AUE_LearningPlayerController`.

Создан плагин `HomeworkPlugin`, который при запуске игрового мира создаёт визуальный объект перед игроком.

После замечаний преподавателя плагин был доработан:

- `AUE_LearningGameMode` и `AUE_LearningPlayerController` связаны в C++ коде;
- визуальный объект вынесен в отдельный Blueprint-ассет `BP_HomeworkCube`;
- плагин спавнит готовый Actor через `SpawnActor`;
- лишние вызовы настройки масштаба и пробуждения физики удалены.

## Домашняя работа 2

Добавлен персонаж `Alien Soldier` с набором дополнительных анимаций.

Настроена анимационная система:

Добавлено оружие персонажа:

- C++ класс `TPWeaponActor`;
- Blueprint оружия `BP_RifleWeapon`;
- оружие задаётся через настройку `Weapon Class` в `BP_TPPlayerCharacter`;
- оружие крепится к сокету на скелете персонажа;
- левая рука подтягивается к IK-точке на оружии.

Создан отдельный модуль `HW3Module`, содержащий тестовый C++ Actor.

Создан отдельный плагин `HW3Plugin`, содержащий тестовый C++ Actor.

В классе персонажа добавлены функции для создания тестовых акторов из модуля и плагина перед игроком. Для вызова этих функций настроены отдельные клавиши через Enhanced Input.

После замечаний преподавателя была доработана архитектура персонажа:

- Blueprint-геттеры состояния персонажа вынесены в публичный интерфейс;
- геттеры состояния сделаны `BlueprintPure`;
- независимые булевые флаги движения заменены на `ETPMovementState`;
- режимы `Running`, `Walking`, `Sprinting`, `Aiming` представлены через `enum class`;
- скорость и режим поворота обновляются централизованно через `SetMovementState`.

Для анимаций добавлен C++ класс `TPCharacterAnimInstance`.

В него перенесены анимационные производные данные:

- скорость движения;
- направление движения;
- состояние падения;
- состояние приседа;
- подготовка к приземлению.

Предсказание приземления перенесено из `TPPlayerCharacter` в `TPCharacterAnimInstance`.

Подготовка к приземлению теперь рассчитывается не по фиксированной дистанции до земли, а по прогнозируемому времени до удара:

- вниз выполняется trace для определения расстояния до земли;
- учитываются текущая вертикальная скорость и гравитация;
- вычисляется `TimeToImpact`;
- anticipation pose включается, когда `TimeToImpact` меньше заданного `LandingLeadTime`.

Так момент включения landing-анимации становится стабильнее при разных скоростях падения и разных высотах.

## Домашняя работа 4

В рамках работы использована уже созданная иерархия персонажей:

- `TPBaseCharacter` — базовый C++ класс персонажа;
- `TPPlayerCharacter` — основной игровой персонаж на основе базового класса;
- управление реализовано через Enhanced Input;
- персонажу подключены кастомные анимации Alien Soldier через Animation Blueprint, Blend Space и State Machine.

Расширена система взаимодействия с объектами сцены.

Интерфейс `Interactable` дополнен методами:

- `Interact` — выполнить взаимодействие;
- `CanInteract` — проверить возможность взаимодействия;
- `GetInteractionPrompt` — получить текст подсказки;
- `OnFocused` — реакция на наведение / фокус;
- `OnUnfocused` — реакция на потерю фокуса.

Создан базовый класс интерактивного объекта `InteractableActor`, реализующий общую логику взаимодействия, подсказки и фокусировки.

Добавлены 3 категории интерактивных объектов:

- `PickupInteractableActor` — предмет для подбора;
- `ActivatorInteractableActor` — переключатель, управляющий другим Actor;
- `InfoInteractableActor` — информационный объект.

Добавлен `InteractionDetectorComponent`, который:

- ищет интерактивные объекты в радиусе игрока;
- выбирает ближайший доступный объект;
- вызывает `OnFocused` / `OnUnfocused`;
- обновляет текущий объект взаимодействия;
- обновляет подсказку после изменения состояния объекта.

Для визуального выделения интерактивных объектов реализован outline через `CustomDepth / CustomStencil` и post-process material.

С помощью CommonUI реализована экранная подсказка взаимодействия:

- создан `InteractionPromptWidget` на основе `UCommonUserWidget`;
- создан Blueprint-виджет `WBP_InteractionPrompt`;
- текст подсказки берётся из `GetInteractionPrompt`;
- подсказка появляется при наведении на интерактивный объект;
- подсказка скрывается при потере фокуса;
- текст обновляется динамически после взаимодействия, например `Show info` / `Hide info`.

Дополнительно старый тестовый объект взаимодействия из ДЗ 2 адаптирован под новую систему взаимодействия.

Для этого создан Blueprint-наследник `BP_TestInteractable_HW2` от базового класса `InteractableActor`. Объект работает через общую систему `InteractionDetectorComponent`, получает outline при фокусе и отображает CommonUI-подсказку.

При взаимодействии с объектом над ним появляется надпись:

`Object from homework 2`

Надпись реализована через `TextRenderComponent` внутри Blueprint и скрывается через несколько секунд после взаимодействия.

Система ввода доработана: вместо отдельных `UInputAction*` в персонаже используется `TPInputConfig` Data Asset с привязкой действий через `GameplayTag`. Это позволяет менять Input Action assets без добавления новых полей в `TPPlayerCharacter`.

CommonUI-подсказка взаимодействия использует `UCommonTextBlock`. Клавиша взаимодействия отображается динамически: она берётся из `InputConfig` и `DefaultMappingContext`, поэтому при изменении клавиши в `IMC_Default` текст подсказки обновляется без правки C++.

## Домашняя работа 5 — создание NPC  
### Промежуточный этап

Начата реализация масштабируемой системы NPC, рассчитанной не только на выполнение домашней работы, но и на дальнейшее развитие проекта.

### Базовая архитектура NPC

Добавлены C++ классы и структуры данных:

- `TPNPCCharacter` — базовый класс NPC;
- `TPNPCAIController` — AI-контроллер NPC;
- `TPNPCDefinition` — Data Asset с настраиваемыми параметрами NPC;
- `TPNPCTypes` — общие типы и перечисления для системы NPC.

Созданы два типа NPC:

- `BP_NPC_Bandit` — враждебный NPC;
- `BP_NPC_Researcher` — нейтральный NPC.

Параметры конкретных NPC вынесены в отдельные Data Asset:

- `DA_NPC_Bandit`;
- `DA_NPC_Researcher`.

Это позволяет создавать новые разновидности NPC без дублирования основной C++-логики.

### Поведение враждебного NPC

Для разбойника создан State Tree:

- `ST_NPC_Bandit`.

На текущем этапе реализованы состояния:

- `Move To Random Point` — выбор случайной точки на NavMesh и движение к ней;
- `Wait Before Next Point` — пауза между этапами патрулирования;
- `Chase Target` — преследование обнаруженной цели;
- `Fire At Target` — остановка и выполнение тестового выстрела по цели.

Для State Tree добавлены переиспользуемые C++-задачи и вычисляемые данные:

- поиск случайной точки патрулирования;
- переключение скорости передвижения NPC;
- получение текущей цели;
- вычисление дистанции до цели;
- проверка дистанции стрельбы;
- проверка прямой видимости цели;
- тестовый одиночный выстрел из текущего оружия.

### Обнаружение игрока

В `TPNPCAIController` подключена система `AI Perception`.

NPC:

- обнаруживает игрока;
- назначает его текущей целью;
- переходит от патрулирования к преследованию;
- сохраняет цель при кратковременной потере видимости;
- забывает цель только после заданной задержки;
- возвращается к патрулированию после потери цели.

Задержка забывания цели вынесена в настройки NPC через `TargetForgetDelay`.

### Анимации NPC

Для NPC создан отдельный Animation Blueprint:

- `ABP_NPC_Humanoid`.

Добавлены:

- Blend Space передвижения;
- вычисление скорости и направления движения;
- анимации патрулирования и преследования;
- поддержка удержания оружия двумя руками.

Для левой руки используется `Two Bone IK`:

- винтовка прикрепляется к сокету правой кисти;
- левая кисть процедурно подтягивается к `LeftHandIKTarget`, расположенному внутри оружия.

### Общая система экипировки

Логика создания и хранения оружия вынесена из класса игрока в общий компонент:

- `TPWeaponEquipmentComponent`.

Компонент используется базовым персонажем и подходит как для игрока, так и для NPC.

Добавлен Data Asset оружия:

- `TPWeaponDefinition`;
- `DA_Weapon_Rifle`.

Через него задаются:

- класс Actor оружия;
- имя сокета крепления;
- индивидуальная поправка положения оружия;
- точка выхода выстрела.

Одна и та же винтовка `BP_RifleWeapon` теперь может использоваться главным персонажем и враждебным NPC.

### Подготовка системы стрельбы

В `TPWeaponActor` добавлен компонент:

- `MuzzlePoint` — точка выхода пули у среза ствола.

Для проверки направления оружия реализована отладочная визуализация:

- сфера в позиции `MuzzlePoint`;
- линия вдоль направления ствола.

Добавлен временный тестовый метод одиночного выстрела:

- `DebugFireOnce`.

Метод выполняет line trace от `MuzzlePoint` до текущей цели NPC и выводит результат в лог.

Для выстрелов создан отдельный trace-канал:

- `WeaponTrace`.

Это отделяет обработку попаданий оружия от каналов взаимодействия, обзора AI и стандартного `Visibility`.

### Текущее состояние

На промежуточном этапе реализовано:

- патрулирование разбойника;
- обнаружение игрока;
- преследование игрока;
- возврат к патрулированию после потери цели;
- удержание винтовки двумя руками;
- стрельба одиночными тестовыми trace-выстрелами с заданным интервалом;
- блокирование выстрелов препятствиями через канал `WeaponTrace`.

Урон, анимации выстрела, визуальные эффекты, звук и полноценная логика нейтрального NPC будут добавлены на следующих этапах.
