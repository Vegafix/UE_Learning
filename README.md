Учебный проект на Unreal Engine 5.7 для выполнения домашних работ по курсу Unreal Engine Game Developer.

---

## Домашняя работа 1

Реализован автоматический тест `UE_Learning.PlayerControllerDefaults`, который проверяет валидность CDO пользовательского `AUE_LearningPlayerController`.

Создан плагин `HomeworkPlugin`, который при запуске игрового мира создаёт визуальный объект перед игроком.

После замечаний преподавателя плагин был доработан:

- `AUE_LearningGameMode` и `AUE_LearningPlayerController` связаны в C++ коде;
- визуальный объект вынесен в отдельный Blueprint-ассет `BP_HomeworkCube`;
- плагин спавнит готовый Actor через `SpawnActor`;
- лишние вызовы настройки масштаба и пробуждения физики удалены.

Создан отдельный модуль `HW3Module`, содержащий тестовый C++ Actor.

Создан отдельный плагин `HW3Plugin`, содержащий тестовый C++ Actor.

В классе персонажа добавлены функции для создания тестовых акторов из модуля и плагина перед игроком. Для вызова этих функций настроены отдельные клавиши через Enhanced Input.

После замечаний преподавателя была доработана архитектура персонажа:

- Blueprint-геттеры состояния персонажа вынесены в публичный интерфейс;
- геттеры состояния сделаны `BlueprintPure`;
- независимые булевые флаги движения заменены на `ETPMovementState`;
- режимы `Running`, `Walking`, `Sprinting`, `Aiming` представлены через `enum class`;
- скорость и режим поворота обновляются централизованно через `SetMovementState`.

Для анимаций добавлен C++ класс `TPCharacterAnimInstance`.

В него перенесены анимационные производные данные:

- скорость движения;
- направление движения;
- состояние падения;
- состояние приседа;
- подготовка к приземлению.

Предсказание приземления перенесено из `TPPlayerCharacter` в `TPCharacterAnimInstance`.

Подготовка к приземлению теперь рассчитывается не по фиксированной дистанции до земли, а по прогнозируемому времени до удара:

- вниз выполняется trace для определения расстояния до земли;
- учитываются текущая вертикальная скорость и гравитация;
- вычисляется `TimeToImpact`;
- anticipation pose включается, когда `TimeToImpact` меньше заданного `LandingLeadTime`.

Так момент включения landing-анимации становится стабильнее при разных скоростях падения и разных высотах.

## Домашняя работа 4

В рамках работы использована уже созданная иерархия персонажей:

- `TPBaseCharacter` — базовый C++ класс персонажа;

Интерфейс `Interactable` дополнен методами:

- `GetInteractionPrompt` — получить текст подсказки;
- `OnFocused` — реакция на наведение / фокус;
- `OnUnfocused` — реакция на потерю фокуса.

Добавлены 3 категории интерактивных объектов:

- `PickupInteractableActor` — предмет для подбора;
- `ActivatorInteractableActor` — переключатель, управляющий другим Actor;

Добавлен `InteractionDetectorComponent`, который:

- ищет интерактивные объекты в радиусе игрока;
- выбирает ближайший доступный объект;
- вызывает `OnFocused` / `OnUnfocused`;
- обновляет текущий объект взаимодействия;
- обновляет подсказку после изменения состояния объекта.

Для визуального выделения интерактивных объектов реализован outline через `CustomDepth / CustomStencil` и post-process material.

С помощью CommonUI реализована экранная подсказка взаимодействия:

- создан `InteractionPromptWidget` на основе `UCommonUserWidget`;
- создан Blueprint-виджет `WBP_InteractionPrompt`;
- текст подсказки берётся из `GetInteractionPrompt`;
- подсказка появляется при наведении на интерактивный объект;
- подсказка скрывается при потере фокуса;
- текст обновляется динамически после взаимодействия, например `Show info` / `Hide info`.

Дополнительно старый тестовый объект взаимодействия из ДЗ 2 адаптирован под новую систему взаимодействия.

Для этого создан Blueprint-наследник `BP_TestInteractable_HW2` от базового класса `InteractableActor`. Объект работает через общую систему `InteractionDetectorComponent`, получает outline при фокусе и отображает CommonUI-подсказку.

При взаимодействии с объектом над ним появляется надпись:

`Object from homework 2`

Надпись реализована через `TextRenderComponent` внутри Blueprint и скрывается через несколько секунд после взаимодействия.

Система ввода доработана: вместо отдельных `UInputAction*` в персонаже используется `TPInputConfig` Data Asset с привязкой действий через `GameplayTag`. Это позволяет менять Input Action assets без добавления новых полей в `TPPlayerCharacter`.

CommonUI-подсказка взаимодействия использует `UCommonTextBlock`. Клавиша взаимодействия отображается динамически: она берётся из `InputConfig` и `DefaultMappingContext`, поэтому при изменении клавиши в `IMC_Default` текст подсказки обновляется без правки C++.

## Домашняя работа 5

В рамках домашней работы продолжена разработка общей системы NPC и квестовых сценариев. Задача выполнена не как отдельный изолированный пример, а как развитие уже существующей архитектуры проекта: базовых персонажей, системы взаимодействия, AI, оружия, UI и Gameplay Ability System.

### Базовая архитектура NPC

Для NPC используется общая иерархия персонажей:

- `TPBaseCharacter` — общий базовый класс персонажа;
- `TPNPCCharacter` — базовый класс NPC;
- `TPPlayerCharacter` — игровой персонаж;
- `TPNPCAIController` — AI Controller для NPC;
- `TPNPCDefinition` — Data Asset с параметрами конкретного NPC;
- `TPNPCTypes` — общие типы и перечисления для NPC.

Созданы два типа NPC:

- `BP_NPC_Bandit` — враждебный NPC;
- `BP_NPC_Researcher` — нейтральный NPC-квестодатель.

Параметры конкретных NPC вынесены в Data Asset:

- `DA_NPC_Bandit`;
- `DA_NPC_Researcher`.

Через Data Asset задаются принадлежность к команде, параметры движения, возможность взаимодействия, текст подсказки, оружие по умолчанию и другие настройки. Это позволяет создавать новые разновидности NPC без дублирования основной C++-логики.

### Поведение враждебного NPC

Для разбойника используется State Tree:

- `ST_NPC_Bandit`.

В поведении враждебного NPC реализованы состояния:

- патрулирование по случайным точкам NavMesh;
- ожидание между точками патруля;
- обнаружение игрока;
- преследование цели;
- остановка на дистанции атаки;
- стрельба по цели.

Для State Tree добавлены переиспользуемые C++-задачи и вычисляемые данные:

- поиск случайной точки патрулирования;
- переключение скорости NPC;
- получение текущей цели;
- вычисление дистанции до цели;
- проверка дистанции стрельбы;
- проверка прямой видимости;
- выполнение одиночного выстрела через оружие NPC.

Обнаружение игрока реализовано через `AI Perception` в `TPNPCAIController`. NPC запоминает цель при кратковременной потере видимости и возвращается к патрулированию после заданной задержки забывания цели.

### Поведение нейтрального NPC

Нейтральный NPC `BP_NPC_Researcher` используется как квестодатель.

Для него добавлен компонент:

- `TPQuestGiverComponent`.

Компонент отвечает за:

- обработку взаимодействия с NPC;
- открытие окна предложения задания;
- запуск цели после принятия задания;
- обновление подсказки взаимодействия;
- обработку возврата игрока с артефактом;
- завершение задания после сдачи результата.

Логика выдачи задания вынесена из Level Blueprint в переиспользуемый компонент. Это снижает связанность сцены и позволяет использовать тот же подход для других NPC-квестодателей.

### UI предложения задания

Для окна предложения задания используется виджет:

- `TPQuestOfferWidget`;
- `WBP_QuestOffer`.

Виджет применяется в двух сценариях:

- предложение задания от нейтрального NPC;
- переговоры с вражеским NPC.

В окне поддерживаются:

- заголовок;
- описание;
- кнопка принятия;
- кнопка отказа;
- закрытие через `Esc`;
- подтверждение через UI-кнопку;
- постановка игры на паузу на время диалога.

### Система целей

Для управления целью используется Actor:

- `TPLevelObjectiveManager`.

В рамках домашней работы он расширен до сценарной логики с квестовым предметом.

Добавлены режимы завершения цели:

- уничтожить всех целевых NPC;
- получить квестовый предмет;
- уничтожить цели и получить квестовый предмет.

Для текущего сценария используется получение предмета с последующим возвратом к квестодателю. Это позволяет отделить сам факт получения артефакта от финальной сдачи задания.

`TPLevelObjectiveManager` также выбирает одного случайного NPC из списка целей, который может выдать квестовый предмет при смерти. Благодаря этому при наличии нескольких разбойников артефакт появляется только один раз.

### Квестовый предмет

Добавлен квестовый предмет:

- `TPQuestItemActor`;
- `BP_QuestArtifact`.

Предмет реализован через существующую систему взаимодействия `Interactable`. Он имеет идентификатор:

- `BanditArtifact`.

При подборе предмет сообщает `TPLevelObjectiveManager`, что нужный артефакт получен.

Для выпадения предмета добавлен компонент:

- `TPQuestItemDropComponent`.

Компонент вешается на NPC и подписывается на событие смерти персонажа. После смерти выбранного NPC он создаёт `BP_QuestArtifact` рядом с телом. Предмет использует физику и корректно взаимодействует с поверхностью уровня.

### Переговоры с вражеским NPC

Для альтернативного сценария добавлен компонент:

- `TPEnemyNegotiationComponent`.

Компонент размещается на `BP_NPC_Bandit` и обрабатывает взаимодействие с вражеским NPC во время активного задания.

Сценарий переговоров:

1. игрок принимает задание у `BP_NPC_Researcher`;
2. подходит к `BP_NPC_Bandit`;
3. открывает окно переговоров;
4. выбирает вариант получения артефакта;
5. артефакт засчитывается без убийства NPC;
6. игрок возвращается к `BP_NPC_Researcher`;
7. сдаёт задание.

Таким образом, артефакт можно получить двумя способами:

- через сражение и подбор предмета после смерти разбойника;
- через переговоры с вражеским NPC.

### Завершение задания

После получения артефакта задание не завершается автоматически. Игрок должен вернуться к нейтральному NPC и сдать предмет.

Для этого в `TPQuestGiverComponent` добавлен отдельный prompt состояния возврата:

- `TurnInPrompt`.

После сдачи задания вызывается завершение цели и отображается экран завершения. Такой сценарий лучше соответствует структуре квеста: получение задания, выполнение условия, возвращение к квестодателю и получение награды.

### Итоговое состояние

В рамках домашней работы реализованы требования:

- созданы два типа NPC: враждебный и нейтральный;
- для враждебного NPC задано поведение через State Tree и AI Perception;
- нейтральный NPC используется как квестодатель;
- система квестов описывает сценарий взаимодействия с нейтральным NPC;
- реализован сценарий получения артефакта через бой;
- реализован альтернативный сценарий получения артефакта через переговоры с вражеским NPC;
- после получения артефакта игрок возвращается к квестодателю и завершает задание;
- логика вынесена в переиспользуемые C++ компоненты, а Blueprint используется для настройки ассетов, UI и объектов уровня.

## Домашняя работа 6

В рамках домашней работы добавлен отдельный уровень окружения для проверки систем Landscape, Foliage и постпроцессов. Уровень не заменяет существующую карту с персонажем, NPC, оружием и квестовой логикой, а расширяет проект отдельной сценой, на которой можно развивать визуальное окружение и проверять настройки рельефа, растительности и финальной обработки изображения.

### Уровень окружения

Создана отдельная карта:

* `Lvl_HW6_Landscape`.

Карта размещена в папке:

* `Content/Homework/HW6/Maps`.

Для уровня создан Landscape с базовым рельефом: центральной игровой зоной, холмами, низинами, дорожкой и каменистыми участками. Это отделяет окружение от обычных Static Mesh-плоскостей и позволяет использовать специализированную систему рельефа Unreal Engine.

Для поверхности Landscape добавлен материал:

* `M_HW6_Landscape`.

Материал использует Landscape Layers:

* `Grass`;
* `Dirt`;
* `Rock`.

### Система окружения через Foliage

Для наполнения карты использована система Foliage.

Созданы Foliage Type assets:

* `FT_HW6_Grass`;
* `FT_HW6_Bush`;
* `FT_HW6_Rock`.

Через Foliage на Landscape размещены трава, кусты и камни. Объекты распределены с учётом структуры уровня: центральная зона остаётся читаемой для игрока, растительность размещается группами, а камни используются преимущественно на склонах и каменистых участках.

Подготовленные ассеты окружения размещены в структуре:

* `Content/Homework/HW6`.

Так сцена окружения остаётся изолированной по контенту, но сохраняется внутри общего проекта и может быть использована как основа для дальнейшего развития открытой карты, боевой зоны или квестовой локации.

### Постпроцесс

Для визуального изменения сцены добавлен глобальный Post Process Volume.

Создан постпроцесс-материал:

* `M_HW6_PP_NatureTone`.

Материал использует домен `Post Process`, получает изображение сцены через `SceneTexture: PostProcessInput0` и выводит результат через `Emissive Color`. Эффект добавляет мягкое природное тонирование сцены без жёсткого искажения освещения.

`PostProcessVolume` настроен как глобальный для уровня через `Infinite Extent (Unbound)`. Дополнительно используется виньетка, чтобы визуальное изменение карты было заметно при запуске уровня.


### Процедурное окружение через PCG

В качестве дополнительного слоя окружения добавлен PCG Graph:

* `PCG_HW6_RockSlope`.

Граф используется на карте `Lvl_HW6_Landscape` через `PCGVolume_HW6_RockSlope`. PCG получает данные Landscape, создаёт точки на поверхности внутри заданного объёма, применяет случайный масштаб и поворот, после чего размещает подготовленные Static Mesh окружения.

Такой подход отделяет ручную художественную расстановку Foliage от процедурного наполнения повторяемыми объектами. Ручной Foliage остаётся для контролируемой композиции уровня, а PCG может использоваться как расширяемая основа для генерации каменистых склонов, лесных зон и других участков окружения.


### Итоговое состояние

В рамках домашней работы реализованы требования:

* создан отдельный уровень на основе Landscape;
* для Landscape настроен материал со слоями поверхности;
* на Landscape размещены объекты окружения через Foliage;
* добавлен глобальный Post Process Volume;
* создан Post Process Material, изменяющий отображение карты;
* добавлен PCG Graph для процедурного размещения объектов окружения на Landscape;
* сцена окружения вынесена в отдельную структуру `Content/Homework/HW6` и не нарушает существующую архитектуру персонажа, NPC, оружия, UI и квестовой системы.

## Домашняя работа 7

Начата работа над системой звука и визуальных эффектов. На первом промежуточном этапе добавлена звуковая часть без Niagara VFX, чтобы отдельно зафиксировать изменения в архитектуре аудио.

### Звуковая архитектура персонажей

Добавлен компонент `TPCharacterAudioComponent`, который отвечает за звуки, связанные с персонажем:

- воспроизведение шагов левой и правой ноги;
- автоматическое определение момента шага через трассировку от костей стоп;
- воспроизведение сердцебиения при низком уровне здоровья игрока.

Компонент подключён к базовой иерархии персонажей, поэтому его можно использовать как для игрока, так и для NPC без дублирования логики.

Компонент проверяет положение стоп относительно поверхности и запускает звук при посадке ноги на землю. Это позволяет привязать звук к фактическому контакту стопы с поверхностью, включая движение по наклонным участкам и приземление.

### Звуки оружия и попаданий

В `TPWeaponActor` добавлены параметры звука выстрела. Звук воспроизводится после успешного создания projectile, поэтому не запускается при невозможности выстрела.

В `TPBlasterProjectile` добавлены звуки попадания:

- звук попадания в тело;
- звук попадания в голову.

Для определения попадания в голову используется проверка расстояния от точки попадания до socket / bone головы на Skeletal Mesh персонажа. Это заменяет приблизительную проверку по высоте капсулы и позволяет точнее выбирать звук попадания.

### Звуки смерти и окружения

В `TPNPCCharacter` добавлен звук падения мёртвого тела, который вызывается при переходе NPC в состояние смерти.

На уровне добавлен ambient-звук окружения. Он отделён от позиционных звуков персонажей и оружия и используется как общий фон сцены.

### Добавленные ассеты

Для настройки аудио добавлены SoundWave и Attenuation assets в `Content/Audio`:

- звук выстрела;
- звук попадания в тело;
- звук попадания в голову;
- шаг левой ноги;
- шаг правой ноги;
- фоновый ambient;
- звук падения тела;
- сердцебиение при низком здоровье;
- attenuation-настройки для 3D-звуков персонажа и оружия.

### Niagara VFX

Визуальные эффекты перенесены на Niagara.
Добавлены Niagara System assets:

- `NS_HW7_MuzzleFlash` — короткая красная энергетическая вспышка у точки `MuzzlePoint` при выстреле;
- `NS_HW7_ImpactSpark` — эффект попадания projectile в окружение;
- `NS_HW7_NPCImpactBurst` — отдельный мягкий эффект попадания по NPC.

Для Niagara-спрайтов создан общий материал `M_HW7_VFX_SoftSprite`. Он использует `Additive`, `Unlit` и радиальный градиент, чтобы эффекты не выглядели как жёсткие плоские спрайты.

VFX подключены через уже существующие события игровой архитектуры:

- `OnWeaponFired` в `TPWeaponActor` запускает `NS_HW7_MuzzleFlash`;
- `OnProjectileImpact` в `TPBlasterProjectile` выбирает эффект по типу цели:
  - при попадании по NPC запускается `NS_HW7_NPCImpactBurst`;
  - при попадании по окружению запускается `NS_HW7_ImpactSpark`.

Так VFX-система остаётся разделённой по ответственности: C++ отдаёт игровые события, Blueprint выбирает визуальный эффект, а Niagara отвечает за внешний вид.
